02 / Concepts

普通闪电贷、债务模式与循环贷不是一回事

Classic flash loan经典闪电贷

同一交易中无抵押借出资金、执行策略，并在结束前归还本金与费用。还不上，整笔交易回滚。

Aave mode = 2闪电贷债务模式

资金仍先在回调中使用，但结束时不把本金转回池子；Aave 在抵押检查通过后为指定账户建立浮动债务。

Looping循环贷

把资产 A 孤押，借出资产 B，再把 B 换回 A 并重新存入；重复后同时放大抵押和债务。

【官方说明】OKX 循环借贷 FAQ对产品的描述是：存入资产 A、借出资产 B、换成 A 再存入，并按循环次数重复。Aave 治理材料则明确说明，X Layer Loop Tool 的目的就是免去用户手工执行多次 supply、borrow 和 re-supply。

原子性解决的是“做到一半”的执行风险：兑换失败、最小输出不满足、Aave 拒绝新债务或健康因子检查不通过时，相关状态会一起回滚。它不会消除交易完成后的利率、价格、流动性、治理和清算风险。

06 / Atomic Sequence

一笔交易内的完整时序

1Aave 放款

aXETH 储备向 LoopExecutor 转出 0.02335872 xETH。

2叠加本金

LoopExecutor 从用户拉取 0.01 xETH，总额变为 0.03335872。

3路由兑换

资金进入 OKX Router，并由 UniV3 适配器访问 xBETH/xETH 池。

4收到 xBETH

执行器收到约 0.032880614 xBETH。

5代表用户存入

执行器把全部 xBETH supply 到 Aave，受益人为用户。

6取得抵押凭证

用户收到同数量 aXlrxBETH，Aave 启用该资产作抵押。

7建立长期债务

Aave 校验账户后铸造 0.02335872 xETH 的 variable debt。

【源码确认】executeOperation 是 Aave 把资金交给接收器后的回调入口；兑换与 supply 都发生在回调期间。回调返回后，Aave 才进入“归还资金”或“建立债务”二选一的结算分支。

关键误区：这里没有“先把闪电贷还回去，再另借一笔”。债务模式直接以 releaseUnderlying = false 调用借款逻辑：资金早已在回调前释放，结算阶段只记债务，不再次转出资金。

08 / Protocol Logic

Aave 为什么允许闪借本金变成长期债务

接口层

【源码确认】Aave IPool.flashLoan 接口把 interestRateModes 定义为：0 不开债、无法收回则回滚；1 已弃用；2 按闪借金额向 onBehalfOf 地址建立浮动利率债务。

执行层

【源码确认】FlashLoanLogic先转出资产并调用接收器；模式为 0 时走 repayment，非 0 时走 BorrowLogic.executeBorrow，并设置 releaseUnderlying: false。

// 逻辑化简，非逐字源码
transferUnderlyingTo(receiver, amount);
receiver.executeOperation(...);

if (mode == 0) {
  pullBack(amount + premium);
} else {
  executeBorrow(onBehalfOf, amount, mode, releaseUnderlying = false);
  premium = 0;
}

【治理材料】Aave 关于 X Layer Loop Tool 的提案明确写明：工具让用户无需手动完成多次 supply、borrow 和 re-supply，并申请把指定合约加入 FlashBorrower 白名单以免除闪电贷费用。该白名单只豁免指定合约的 flashloan fee，不改变储备或风险参数。

“premium 为 0”要分清原因：Aave 核心逻辑对转成债务的 mode=2 分支本就不收 premium；白名单则还可免除指定合约执行普通闪电贷操作时的费用。两者不能混为一谈，更不能推广为所有 Aave 闪电贷都免费。
09 / Loop Equivalence

为什么经济结果等价于循环贷

传统循环贷每一轮把新增借款换成抵押品再存入。若每轮债务比例为 q，忽略手续费与价格影响，抵押规模是一条几何级数：

C = E × (1 + q + q² + …) = E / (1 − q)
D = C − E = E × q / (1 − q)
Leverage = C / E = 1 / (1 − q)

本笔交易直接指定最终需要的债务 D = 0.02335872 xETH，一次性拿到 E + D = 0.03335872 xETH 进行兑换，跳过中间每一轮，却落在几乎相同的最终资产负债表上。

名义部署额 / 初始本金3.335872×
最终抵押 / 净权益3.336936×
实际债务 / 抵押价值70.0324%
88% LTV 理论极限8.3333×

【机制推导】88% LTV 的无摩擦无限循环理论值是 1 / (1 − 0.88) = 8.33×，但本笔并未用满额度。实际债务率约 70.03%，对应约 3.34× 的最终仓位。

“等价”仅指最终抵押、债务与权益关系近似一致。一笔聚合交换和多轮小额交换在价格影响、手续费、交易排序与失败概率上并不完全相同。

12 / Controls & Risks

原子化提高执行完整性，但风险链更长

交易内控制失败即回滚

minSwapOut、内层 DEX 最小输出、minHealthFactor、Aave 抵押检查和 eMode 约束共同决定交易能否落地。

交易后风险债务持续存在

xETH 浮动借款利息继续累积；抵押收益、借款 APY、奖励与汇率变化决定净 carry，健康因子会随时间变化。

组合依赖多合约信任链

Aave、LoopExecutor、OKX Router/适配器、UniV3 池、xETH 与 xBETH 的发行和预言机共同影响结果。
